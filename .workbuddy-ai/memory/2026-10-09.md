### Lexicographic pairs — done, and they prove a LIMIT

- `Ranking { first, second: Option<usize> }` (public). A pair is `strict` when
  the first measure falls, or when it holds and the second falls.
  `Terminating { ranking }`; `classify_ranking`; certificate says
  `terminates F ranking k+l cycles ...`.
- **Measured: `compiler.ref` 343 → 330 unproven functions; corpus 430 → 417.**
  Zero infeasible. **And 2× faster (3.9 s → 2.0 s)** — classification is now
  precomputed once per ranking, not once per function.
- **CORRECTION — the important part.** I claimed pairs would tolerate an edge
  unbounded at k₂ when k₁ decreases, and would attack the **24 one-call-away**
  functions. **Both wrong.** A pair is `unknown` wherever its *first* measure is
  (the pair's ranking contains the first measure). So pairs break non-decreasing
  **cycles** but can **never bound a call no measure bounds**. Pinned as
  `a_pair_can_never_bound_a_call_its_first_measure_cannot`.
- **The measure direction is CLOSED.** Do not try deeper paths, more measures, or
  other combinations — none can bound a computed call. The measure must bound
  *the call itself*, and a call in argument position has no static size.
